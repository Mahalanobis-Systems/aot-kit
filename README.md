# AOT Kit

The optimizations themselves: one Claude Code skill for each change we have researched that can
make a production agent cheaper, faster or better. Each skill says what the change is, the
signals in the agent's code, traces and eval results that say it applies, which evidence tier it
belongs to, and how to measure it.

A Claude Code plugin from Mahal Systems, part of **AOT, the Agent Optimization Toolkit**:
- [aot-evals](https://github.com/Mahalanobis-Systems/aot-evals) builds and runs the evals that
  decide whether a change helped.
- **aot-kit** (this repo) holds the changes to try, and the library of evidence behind them.

> **Status: placeholders.** Every skill is generated from its library entry and describes its
> optimization. None yet walks an agent through detecting, applying and measuring it; each ends
> with a **To build** checklist.

## How to run

```bash
claude plugin marketplace add Mahalanobis-Systems/aot-kit
claude plugin install aot-kit@aot-kit
```

Or, inside Claude Code, `/plugin marketplace add Mahalanobis-Systems/aot-kit` and
`/plugin install aot-kit@aot-kit`. Restart Claude Code, then, in your agent's repository,
`/aot-kit:start` lists the optimizations by tier, or invoke one directly, e.g.
`/aot-kit:bound-tool-output`.

A new release comes out most weeks. Update with `claude plugin marketplace update aot-kit` and
`claude plugin update aot-kit@aot-kit`, or turn on auto-update for the marketplace.

## Where the optimizations come from

[`library/`](library/) is the record: one entry per optimization in `library/entries/<slug>.yaml`,
with its tier, the signals that say it applies, how to measure it, its expected impact and every
source of evidence, each with its own numbers and date. The skills, `catalog.yaml` and the lists
below are generated from it (`make render`), and so is the public library at
[mahalsystems.ai/aot/optimizations](https://mahalsystems.ai/aot/optimizations/). New
optimizations and new evidence go into an entry, never into a skill's generated part.

The library holds 60 optimizations: 32 techniques and 28 patterns from VeRO's pattern library
(Scale AI, [arXiv 2602.22480](https://arxiv.org/abs/2602.22480)), kept where no technique already
makes the same change. Another 31 patterns are folded into the entry that makes the same change
(shown under *Covers*), and a few ids are left out as optimizer-side practices rather than changes
to an agent. `catalog.yaml` records every id, its skill, tier and categories, what each skill
absorbs, and what was left out and why.

A tier says what evidence a change needs before it can be recommended; `library/vocabulary.yaml`
defines the four. An optimization that can sit in more than one tier is listed under the lowest;
its skill names them all.

## Contributing

New evidence, corrections and results from running these changes on real agents are the most
useful contributions: [open an issue](https://github.com/Mahalanobis-Systems/aot-kit/issues/new/choose)
or a pull request. [CONTRIBUTING.md](CONTRIBUTING.md) says what makes good evidence, how an
entry is written, and how contributions are decided and released (weekly, credited in the
changelog). To work on the library:

```bash
make render   # regenerate the skills, catalog.yaml and the lists from library/
make check    # validate the entries; fail if anything generated is stale
claude --plugin-dir .   # try your working copy of the skills in Claude Code
```

Versions follow [Semantic Versioning](https://semver.org/); see [CHANGELOG.md](CHANGELOG.md).
Security problems: [SECURITY.md](SECURITY.md).
