## What it is

Have the model write the task as a program before it reads any untrusted data, and let an interpreter that tracks where every value came from decide which tool calls may run. Attack success stayed at or below 1.8% across five models under an adaptive attack (up to 58.6% undefended) and at 0% on three computer-use suites, but it is the costliest defense in utility: 26.3 to 52.6% of clean AgentDojo tasks against 63.2 to 89.5% undefended, a gap that narrowed to 5.4 to 7.2 points only with frontier models (GPT-5.5, o3), and far wider outside AgentDojo (33.7% against 82.5% on AppWorld, 0% against 82.2% on Terminal-Bench, 13.17% against 55.12% for whole-task programs on WebArena). Use it where the request alone fixes the actions and a hard block on exfiltration is worth lost tasks and about 3.5x the latency; for GUI work, writing a fresh small program for each step kept 53.55% on WebArena in its authors' benign runs. The guarantee holds only where label tracking reaches: retries, error messages, untaken branches and agent-to-agent messages have all been shown to leak, and in one demonstration an attacker's on-screen notice steered the quarantined model's click target.

## When it applies

- **In the code:** The privileged model sees only the request, trusted context and tool descriptions with return schemas, and writes the task as a program; a custom interpreter labels every value with its sources and readers and propagates labels through operations, string formatting and control flow, including untaken branches; untrusted content is parsed only by a model with no tools and a typed output; each side-effecting tool has a policy on argument sources and readers; repair retries and error messages stay inside the checked boundary.
- **In traces:** Policy denials and user confirmations per task; privileged-model retries per task; no executed call whose arguments carry untrusted labels unless a policy allows it; no tool-derived text in another agent's instruction.
- **In eval results:** Static and adaptive injection suites (AgentDojo with per-tool policies, plus data-dependent tasks and realistic suites converted from utility benchmarks such as AppWorld or Terminal-Bench, or WebArena for GUI agents); benign utility and utility under attack; the share of attacks that reach their injection point; tokens and latency per task; share of tasks with a policy denial; excess privilege left open.
- **Probes:** Injected data that tries to add a call, set a write argument, substitute a lookalike value of the expected type, misdirect a click target, leak a private value through a branch or a retry, or cross an agent boundary inside instruction text.

## How (outline)

1. Start from the baseline: your current tool loop (7.d.iii) and a cheaper check on where write arguments came from (argument provenance or per-task policies), same model, on an injection suite with static and adaptive attacks. Frontier models already resist template attacks undefended (0.3% for Claude-Haiku-4.5, 0.0% for GPT-5.5), but an agentic attacker swarm still found a working injection against undefended Gemini 4 Argon in 34% of the authors' own 100 synthetic tool-use scenarios (harmless off-task goals, the model's out-of-model defenses off) and against Gemini 3.8 Flash in 90%, so static numbers alone misstate both the risk and the gain. Sort tasks by whether the request alone fixes the actions, and test on your own task mix, not AgentDojo alone: a program written before reading data cannot do "the actions specified in the email" (no model solved it), and on realistic suites CaMeL kept 33.7% of AppWorld tasks against 82.5% undefended and 0% of Terminal-Bench tasks against 82.2%, and could not run against VitaBench's simulated customer at all. For those tasks contain the input (10.c.i) and gate the action (10.b.i) instead.
2. Give the privileged model only the request, trusted context and tool descriptions with full return schemas, and have it write the whole task as a program in a restricted Python subset: undocumented tool outputs caused 13 of Claude 3.5 Sonnet's 15 Travel failures, and a follow-up had to add return schemas to every tool to reach usable utility. Parse untrusted content only through a quarantined model call with no tools and a typed output schema; it can be a cheaper model (Claude 3.5 Haiku under Claude 4 Sonnet cost about 1% utility for about 12% lower cost per median task) (1.b.i). A narrow type does not make a value safe: an injected lookalike sender, handle or link has the same type as the real one. Before the program uses such a value, verify it against an independent trusted source (a contact book, official documentation) rather than asking the user each time: on computer-use tasks whose injection substitutes the needed value, one design that did this completed 50.9 to 69.2% at 0% attack success, where a whole-task CaMeL program also held 0% but completed 18.8 to 29.5% and the undefended agent was hijacked in 38.5 to 43.6%.
3. Run the program in a custom interpreter that attaches sources and allowed readers to every value and propagates them through every operation, string formatting and control flow, including assignments on branches not taken: an independent audit found CaMeL's interpreter dropped labels in both places. Keep repair retries inside the checked boundary: never return raw error text derived from tool output to the privileged model (an error message put an attacker's reserve_hotel call into the rewritten program in one test), and cap retries, since each blocked-or-allowed retry leaks a bit.
4. Write a policy for each side-effecting tool on where every argument may come from and who may read what is sent (for example, send_money's recipient and amount only from the user). Without policies, a recipient the quarantined model parsed from a landlord's notice was used for a scheduled payment. Route denials to verification or user confirmation and budget for them: CaMeL's released policies refused 41.5% of calls a task was entitled to make and let every required call through on only 37 of 92 tasks, and turning policies on cut banking utility from 66.7% to 37.5% (GPT-5.2).
5. If agents call agents, pass tool-derived values to the child agent through a separate data channel, never inside its instruction text: with CaMeL in every agent, 0.2% of attacks still got through (0.5% for GPT-4.1, from 36.1%), all by that route, and the separate channel took it to 0.0%.
6. Deploy the whole-task form on strong models and on tasks the request fully specifies: clean utility was 26.3 to 52.6% against 63.2 to 89.5% undefended across five smaller models, but 77.3% against 84.5% for o3 and 82.1% against 87.5% for GPT-5.5 (no policies). If that loss is too high, a cheaper argument-provenance or policy defense kept 59.6 to 63.2% clean utility at 4.4 to 7.7% adaptive attack success on GPT-4o-mini, where CaMeL kept 26.3% at 0.0%. For GUI or other long interactive tasks, write a small program for each step instead of one for the whole task, fixing its queries to untrusted content and how each answer may be used, over a screen whose untrusted regions are masked, and locate click targets on the masked screen: on 400 WebArena tasks with Claude Opus 5, GPT-5.6-Sol and Gemini 3.8 Flash this kept 53.55% against 55.12% undefended and 13.17% for a whole-task program with a GPT-5 planner (benign runs only), and a whole-task program's quarantined locator, reading an attacker's notice, returned another post's downvote button in one demonstration.
7. Measure paired against the baseline, same model and suite: benign utility, utility under attack, attack success under static and adaptive attacks and the share of attacks that actually reach their injection point (only 20 of 48 did on AppWorld under CaMeL), tokens and latency per task (17.30 s against 4.98 s and 5,083 against 8,020 tokens with GPT-4o in one test; 2.73x the input and 2.82x the output tokens for the median task with Claude 3.5 Sonnet in the authors' test; 2.31x the tokens on AppWorld; a per-step GUI program 10.3% more tokens than the undefended agent and about 3x its time), the share of tasks with a policy denial and the excess privilege left open; in production, monitor denials, retries, failed value verifications and tasks the program could not express.

- **Security:** improves, large: 0 of 949 attacks succeeded with policies for o3 and Gemini 2.5 Pro, against 11 and 163 undefended (Debenedetti, Mar 2025); at most 1.8% under static and adaptive attacks across five models, against up to 58.6% undefended (Ma, Jun 2026); 1.21% against 15.62% on AgentDojo and 7.15% against 31.04% on ASB, and an attack reusing the task's tools doubled it (0.95% to 1.90%) (Ji, Nov 2025); 0% on three computer-use suites where the undefended agent reached up to 46.2%, relying on masking untrusted screen regions, with underspecified prompts run in a more specific variant (Seip, Oct 2026); 0 of 20 optimized attacks that reached their injection point on AppWorld, with most never reaching it (Wang, Nov 2026); the undefended baseline is not safe against adaptive attackers: an agentic attacker swarm broke Gemini 4 Argon in 34% of the authors' own 100 synthetic scenarios with harmless off-task goals and out-of-model defenses off, and Gemini 3.8 Flash in 90% (Kurakin, Nov 2026). ## Caveats

The guarantee holds only where labels are tracked and policies are written: an audit found leaks through untaken branches, the retry loop and string interpolation (Garby, Feb 2026), an error message carried an injection into the privileged model (Ji, Nov 2025), tool output written into another agent's instructions got through (Peters-Gill, Oct 2026), an attacker's notice misdirected a quarantined screen locator in one demonstration (Choudhary, Oct 2026), and untrusted data can still choose among the program's branches. Several tests ran CaMeL without its policies (Ji, Nov 2025; Peters-Gill, Oct 2026; Wang, Nov 2026) or on one 16-task suite with wide intervals (Garby, Feb 2026), the strongest utility figure (77.3% for o3) is the authors' own, and the independent tests that left AgentDojo found the largest losses (33.7% on AppWorld and 0% on Terminal-Bench in single runs on one model, with most attacks never reaching their injection point; 13.17% for whole-task programs on WebArena). The designs that recover utility are their authors' own: the per-step program was run without attacks, and value verification trusts some sites that host user content and still kept only 30.6 to 50.5% of benign tasks. Frontier models resist static template attacks undefended (0.3% for Claude-Haiku-4.5, 0.0% for GPT-5.5, 0 of 10 hard computer-use attacks for Claude Opus 5 with its API's built-in classifiers), but an agentic attacker swarm still broke Gemini 4 Argon in 34% of the authors' own synthetic scenarios with harmless off-task goals and out-of-model defenses off (Kurakin, Nov 2026), so the case rests on adaptive attackers and on a hard block on exfiltration.
