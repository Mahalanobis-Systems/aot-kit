## What it is

Restart the coding agent in a fresh session for every item, from a shell loop, and let the repository (plan, progress notes, git history) carry the state between sessions until a cap, budget or stop rule ends the run. It pays on long backlogs with a near-perfect automatic check: 16 such loops on Opus 4.6 built a 100,000-line C compiler that builds Linux 6.9 over nearly 2,000 sessions for just under $20,000, and on 112 long-horizon coding tasks restarting a fresh session on the remaining work raised Opus 4.7's resolve rate from 16.96% to 25.00%. On the strongest models restarting costs speed rather than final quality: against one persistent session at the same budget, a fresh session per task matched final results on Opus 5 and GPT-5.6-Sol but took 11.1 against 7.7 minutes to a first valid solution on Opus 5, and a harness that rebuilt a fresh context for every invocation matched the strongest baseline with 93.1% fewer tokens. The limits: no study compares the plain loop with one long session on the same backlog at matched tokens, a Ralph loop scored lowest of four loop designs (7.84%) in a comparison not controlled for model, new features kept breaking old ones until a CI gate was added, and code erosion rose in 77% of agent trajectories across fresh-container iterations.

## When it applies

- **In the code:** A shell or harness loop that starts a headless agent each iteration with the same prompt file over a plan, task list or progress file, committing per iteration; whether it resumes the previous session (a stop hook or resume flag) or starts a fresh one; iteration, budget and time caps; permission prompts turned off outside a container.
- **In traces:** Iterations; commits; rate-limit events; iterations with no tool calls; consecutive failed iterations; tokens since the last test or score gain; the same item claimed or built twice; approaches retried after being recorded as failed; previously passing tests broken; completion claims while hidden tests fail.
- **In eval results:** Throughput; defect rate of produced work.
- **Judge:** Rate produced commits.
- **Probes:** A queue with a poison task.

## How (outline)

1. Start from the baseline: the same backlog run as one long agent session with the harness's own compaction, or an operator re-prompting it, and log where it stops: it waits for input, declares the job done early, or fills its context. On 112 long-horizon coding tasks one session "usually reaches a shallow dependency prefix", and an outer loop that restarted a fresh session on the remaining work raised resolve rate for every configuration but one (Opus 4.7 16.96% to 25.00%, GPT-5.5 14.29% to 21.43%) (Li, Jul 2026). Use the loop only for a long list of checkable items with an automatic check you trust, since the agent "will solve the wrong problem" unless the verifier is "nearly perfect" (Carlini, Feb 2026); tests, type checkers and builds are the loop's back pressure (Huntley, Jul 2025).
2. Start a new headless process every iteration with the same short prompt file, inside a container that holds only the repository, and log each iteration to its own file: while true; do claude --dangerously-skip-permissions -p "$(cat AGENT_PROMPT.md)" &> agent_logs/agent_$(git rev-parse --short=6 HEAD).log; done (Carlini, Feb 2026). Prefer this to resuming one session: in a framework that resumed each agent's own session after restarts, agents that had declared their work optimal kept repeating that decision, with 98% of the last 1,500 sessions making no tool calls (Zhang, Oct 2026). On the strongest models expect a fresh session to start slower, not finish worse: against one session kept across related 30-minute tasks at the same budget, a fresh session per task reached a first valid solution later (11.1 against 7.7 minutes on Opus 5) but matched final results on Opus 5 and GPT-5.6-Sol (-0.9 and -0.8 points for the persistent session, though it helped Sonnet 4.6 by 7.6) (Qin, Nov 2026). The official Claude Code plugin instead re-feeds the prompt inside one session through a stop hook (Anthropic, Nov 2025): restating the same goal inside one session until the agent declared it complete raised full-task success from 27.50% to 31.25% at 3.6 times the estimated cost, a gain absent in that benchmark's first version (Wang, Aug 2026), and in a comparison not controlled for model a Ralph loop resolved 7.84% against 17.65% and 20.59% for the Claude Code and Codex goal modes (Li, Jul 2026), so run both designs on your own backlog before choosing.
3. Keep state in the repository, not the conversation, and load the same files every iteration: the spec, a plan or fix list, a progress file and README the agent updates, and the git log (see 4.b.iii). Ask for one item per iteration and have the agent search the code before implementing, since a wrong "not implemented" conclusion produces duplicate implementations (Huntley, Jul 2025). Record failed attempts as well as progress, and check each proposed change against them before an expensive run: a production loop re-tested one setting at least six times "despite program.md explicitly stating" not to (Chandran, Sep 2026), and agent-written insight notes handed to fresh sessions did not reliably improve final results (Qin, Nov 2026). Letting the agent pick "the next most obvious" problem works while failing tests are independent (Carlini, Feb 2026); in one controlled study a stateless planner that assigned each next experiment from a harness-built summary beat independent worker choices in all four checkpoint comparisons (Zhang, Oct 2026). For parallel loops, claim an item by pushing a lock file through git so a second claim fails (Carlini, Feb 2026); posted notes did not stop two agents from building the same feature twice (Zhang, Oct 2026).
4. Gate every commit: a CI run so new commits can't break existing tests (added once the agents began breaking existing functionality with each new feature), a --fast mode that runs a 1% or 10% sample of the tests, deterministic per agent, for checks inside an iteration, short test output with details in log files (see 7.b.ii), and a known-good oracle to split a monolithic target (GCC compiled most of the kernel so agents could fix different files) (Carlini, Feb 2026). Keep every completed item's tests enforced as regression checks: regression events appeared under every loop design tested, and agents wrote far fewer tests than the native suites (Li, Jul 2026). Where one iteration costs hours, review the change before it runs: a pre-execution fixer caught 14 latent bugs in its first pass, one of which would have run an 8-GPU job on one device for 10+ hours (Chandran, Sep 2026). Schedule cleanup as well: across fresh-container iterations structural erosion rose in 77% of trajectories and verbosity in 75.5%, and quality prompts lowered the level but not the rate of decline (Orlanski, Mar 2026); Carlini gave one agent the job of coalescing duplicate code.
5. Bound and stop the run: always set an iteration cap (the plugin's default is unlimited), a token or dollar budget and a time limit per iteration; stop when the list is done and a check the agent does not control passes, not on the agent's own completion phrase (the plugin's exact-match phrase cannot express "blocked") (see 7.b.i, 7.b.iii, 9.b.iii). Stop or page a person after a few consecutive failed iterations (one production loop lost 11 in a row to an evaluator timeout "before a human intervened"), and redirect or stop when several iterations add no passing test or score gain: one team's trigger, no 8% relative gain over 5 iterations, was chosen over windows of 3 ("too frequent (firing on noise)") and 8 ("too late") (Chandran, Sep 2026). A model that reads a progress summary and decides the next step or the stop is no free fix: on full coding tasks such controllers ranged from 24.17% (below the 27.50% of no control) to 36.25%, at up to $34.68 against $9.47 per run for restating the goal (Wang, Aug 2026). Budget for scale: 16 loops used 2 billion input and 140 million output tokens, just under $20,000, over two weeks (Carlini, Feb 2026).
6. Measure: run the baseline, the in-session re-prompting design and the fresh-process loop on the same backlog, model and dollar budget, several runs each; score with an end-to-end suite the agents never see plus complexity and duplication of the final code, read at several budget points (one harness trailed on all four software tasks at 25% of the budget and led on all four at 100%, Zhang, Oct 2026; a persistent session's mean lead of 24.0 points at 25% of the budget shrank to 1.2 at the deadline, Qin, Nov 2026); per iteration, log tokens, dollars, wall time, commits, tests gained and broken, failed iterations, iterations with no tool calls and tokens since the last improvement.

## Expected impact

- **Quality:** mixed, medium: long backlogs with a near-perfect check: 16 loops built a 100,000-line C compiler that builds Linux 6.9 on x86, ARM and RISC-V and passes 99% of most compiler test suites, but its output is less efficient than GCC with all optimizations disabled and new features frequently broke existing ones (Carlini, Feb 2026); restarting a fresh session on the remaining work raised resolve rate from 16.96% to 25.00% for Opus 4.7 on 112 long-horizon tasks, but a Ralph loop resolved 7.84% against 17.65% to 24.11% for goal modes and dynamic workflows, not controlled for model (Li, Jul 2026); a fresh session per task matched a persistent session's final results on Opus 5 and GPT-5.6-Sol and trailed it by 7.6 points on Sonnet 4.6 (Qin, Nov 2026); restating the goal inside one session 27.50% to 31.25% (Wang, Aug 2026); a fresh-context harness had the best final result on every task, 1112.0 against 1275.7 kernel cycles for the strongest baseline (Zhang, Oct 2026); across fresh-container iterations erosion rose in 77% of trajectories and core pass rate fell from 64.6% to 35.5% (Orlanski, Mar 2026); no study against one long session on the same backlog at matched tokens
- **Cost:** degrades, large: nearly 2,000 sessions, 2 billion input and 140 million output tokens, just under $20,000 (Carlini, Feb 2026); a framework resuming long sessions kept spending until 1B tokens after its last improvement at 231M, while a fresh-context harness reached the strongest baseline's kernel result with 67.9M against 986.3M tokens and its planner used under 0.6% of tokens (Zhang, Oct 2026); restating the goal inside one session cost $9.47 against $2.61 per run, and a model controller up to $34.68 (Wang, Aug 2026); 6.91M billed tokens per task for Opus 4.7 with fresh continuation rounds (Li, Jul 2026); infrastructure failures cost 18% of iterations in one production loop (Chandran, Sep 2026); mean cost per iteration grew 2.2x from first to last checkpoint (Orlanski, Mar 2026)
- **Performance:** mixed, small: a fresh session per task reached a first valid solution later than one persistent session at the same budget (11.1 against 7.7 minutes on Opus 5, 8.5 against 6.1 on GPT-5.6-Sol, 18.7 against 9.5 on Kimi K3) but largely caught up by the deadline, a mean gap of 1.2 points (Qin, Nov 2026); unattended runs replace operator turns: 150+ experiments in three weeks in one production loop, which also lost 11 consecutive iterations before a human intervened (Chandran, Sep 2026); each fresh session spends significant time re-orienting on a large project and agents will spend hours running tests without a sampled fast mode (Carlini, Feb 2026); going from 1 to 15 parallel workers cut elapsed time 6.6 to 7.3x (Zhang, Oct 2026)
- **Security:** degrades, medium: loops run with permission prompts off (--dangerously-skip-permissions) and push their own commits; Carlini says to run it "in a container, not your actual machine" and saw an agent run pkill -9 bash and end its own loop (Carlini, Feb 2026); one harness ran workers as unprivileged processes under Landlock filesystem limits with restricted network (Zhang, Oct 2026)
- **Governance:** mixed, medium: each iteration leaves a commit, a log named by commit and lock files in git history (Carlini, Feb 2026), but no one reviews each commit and the agent's own "done" is weak: "it is easy to see tests pass and assume the job is done, when this is rarely the case" (Carlini, Feb 2026); the vendor plugin stops on an exact completion phrase and has no iteration cap by default (Anthropic, Nov 2025); a production loop optimized its metric but "never questioned the metric", needed human QA between runs and could not run "completely hands-free" (Chandran, Sep 2026)
- **Brand:** none (unmeasured)

## Caveats

Still no study runs the plain fresh-process loop against one long session with compaction on the same backlog at matched tokens: the benchmark that adds fresh continuation rounds reports tokens only with them, its four-loop comparison (Ralph loop lowest at 7.84%) is not controlled for model, and the matched-budget persistent-versus-reset study uses separate 30-minute research tasks with one run pair per agent. The in-session design's measured gain is small and unstable: restating the goal raised full-task success from 27.50% to 31.25% in the current version of one benchmark but matched no control (18.52%) in its first version, both with one open worker model. Fresh contexts and durable notes do not stop drift or repeats: erosion rose in 77% of agent trajectories, regressions appeared under every loop design tested, and a production loop re-tested a failed setting at least six times despite a note forbidding it. The largest builds are single runs judged by their authors, and what a loop can finish depends on the model: earlier Opus 4 models "were barely capable of producing a functional compiler".
