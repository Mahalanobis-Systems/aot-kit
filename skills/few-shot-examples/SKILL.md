## What it is

Show the model a few solved examples (full input and exact output), or give a data agent commented example queries and an index of verified past queries to retrieve per question. The clear gains are on knowledge the model cannot infer, and they hold on 2026 models and multi-step agents: retrieved past queries raised execution accuracy from 36.1% to 42.9% for GPT6-Luna and from 45.1% to 55.4% for Gemini4-Argon on a benchmark built from reusable queries, one Genie space went from 54% to 77% on 13 questions, removing LinkedIn's example-query index cut correct answers from 49% to 24%, and examples retrieved at each step from a stronger model's runs raised GPT-4.1-mini on the AppWorld API benchmark from 0.28 to 0.55. On strong and reasoning models examples mostly fix the format or a convention rather than the reasoning: Qwen2.5-72B scored 95.83% zero-shot against 95.75% with eight examples on GSM8K once the answer extractor was fixed, five examples moved o1-preview by -2.2 to +1.2 points across six medical benchmarks, and 16 examples of the class GPT-5.4 Thinking kept missing raised its F1 from 0.71 to 0.96 on a synthetic conformance test. Start from a zero-shot baseline, add a few examples only where a paired eval shows a gain, count the input tokens they add, and keep fixed examples in the cached prefix with retrieved ones after it in a stable order.

## When it applies

- **In the code:** A prompt with no worked examples on a task with a fixed output shape; a data agent with no example queries for its custom metrics; a multi-step agent with no examples of the tool calls its tasks repeat; examples kept on a reasoning or strong model with no zero-shot comparison; examples retrieved per request placed before static prompt content, or sent in a different order on each request, so the cached prefix changes on every call.
- **In traces:** Outputs that miss the expected shape or metric definition; repeated queries for the same custom metric; retrieved examples with low similarity to the question, or answers that copy a retrieved pattern that does not fit; agent failures where no retrieved example shows the needed tool call or behavior; questions that need logic from several past queries.
- **In eval results:** Failures that cluster on custom metrics, business logic or an output format the examples would show; no paired zero-shot baseline for the examples in use.

## How (outline)

1. Start from the baseline: the same model zero-shot, with a plain instruction, an explicit output format and a robust answer extractor (9.b.i), on held-out cases. Examples often look like a gain only because they fix the format: Qwen2.5-72B went from 91.58% zero-shot to 95.75% with eight examples on GSM8K, but scored 95.83% zero-shot once the extractor read the boxed answer. On a reasoning model begin with no examples: five examples moved o1-preview by -2.2 to +1.2 points across six medical benchmarks, while a tailored prompt and ensembling helped. Where the alternative to examples is a bigger model, run that arm too: on AppWorld, GPT-4.1-mini with retrieved examples scored 0.55 at 0.15 of the teacher's cost, against 0.51 at 0.56 for zero-shot GPT-4.1.
2. Add examples only where failures cluster on what the instruction and schema cannot carry: a custom metric, business logic, a join path, a value convention, an exact output shape, or a class the model keeps misjudging. That still held for a 2026 thinking model: 16 conformant examples raised GPT-5.4 Thinking from 0.71 to 0.96 F1 on a synthetic battery-passport conformance test (recall on conformant files 0.57 to 0.95). For a data agent, write one example query per custom metric with comments that explain the logic (54% to 77% on 13 questions in one Genie space), and build an example-query index from verified queries in code, wikis and the query log, each with a description embedded for retrieval and refreshed as needed (removing such an index cut correct answers from 49% to 24%). With dozens of metrics, define them once in a view or semantic layer instead (7.a.i): in the same Genie space a view holding the definitions also scored 100%.
3. Make each example the full input and the full desired output, in exactly the target format: in the math study the format benefit fell as more of each example was masked, while the reasoning content was largely ignored (in most settings, replacing half of the example tokens with noise barely changed accuracy). Include worked reasoning only for small or older models, which did gain from it (LLaMA3.2-1B, LLaMA2-7B, Qwen-7B); for strong models even reasoning written by DeepSeek-R1 rarely beat zero-shot. Vary the examples' form so the model does not copy one pattern (3.a.ii).
4. Use a few examples, retrieved per question when the pool is large: on underspecified text-to-SQL, retrieving past queries from the same database raised execution accuracy from 54.27% to 60.95% (67.34% with the right ones), peaking at four examples (61.31%, against 58.36% with one), and on 2026 models retrieved past queries raised GPT6-Luna from 36.1% to 42.9% and 43.5% and Gemini4-Argon from 45.1% to 55.4%. Retrieve broadly, then filter and rerank for precision: whole-question similarity alone reached 59.15%, retrieval precision was 35.53%, and in one failure the model copied a retrieved pattern that did not fit. Expect questions that combine logic from several past queries to stay hard (29.7% against 56.7% for single-source ones with the best design tested). Storing verified queries as reusable parts (whole-query templates, SQL blocks, concept-to-column mappings) and consulting the full schema only when they leave gaps reached 49.9% and 57.5% on those two models with 12.6k and 14.6k input tokens instead of 52.5k and 67.4k, but answering from examples that did not cover the request cost a plain few-shot setup 4.7 points, so check coverage before dropping the schema (5.b.i). For a multi-step tool-using agent, retrieve at each step short windows of successful runs on similar tasks, not whole trajectories: on AppWorld, windows from Claude Sonnet 4.5 runs raised GPT-4.1-mini from 0.28 to 0.55, matched whole trajectories retrieved once (0.54) that cost 60% more, and peaked at five examples (0.57, against 0.49 with one) while cost kept rising.
5. Keep the prefix cacheable (3.b.i): put fixed examples in the static part of the prompt and append retrieved ones after it, next to the question. On a self-hosted engine, also keep the order of retrieved examples stable: sorting them by similarity puts even the same examples in a different order on each request, and in one log-parsing study reusing the order of recent example sets (and the cached copy of an equivalent example) raised the prefix-cache hit rate 1.23 times over plain prefix caching; without it p95 latency was 46.97% higher, with average parsing accuracy unchanged but grouping accuracy on one of 16 datasets falling from 67.8% to 54.4%. In many-shot prompts the edge of similarity selection fades as examples are added, and caching a large fixed set while adding 20 retrieved examples per query matched similarity-only selection at an estimated half the cost at 50 examples and a tenth at 200. Retrieval is not always better: on a tool-selection benchmark, similarity-retrieved examples did not beat zero-shot while random ones did.
6. Keep the pool curated, as the tested setups did: final, successful or verified queries and runs only, filtered by execution count and certification. Grow it where failures cluster: in the AppWorld study 33 of 48 attributed failures were coverage gaps where no retrieved example showed the needed API call, disambiguation or error handling, and a larger pool raised accuracy and cut cost. If the examples come from the agent's own past runs, that is episodic memory (4.c.i): verify them before reuse. Do not add examples where the problem calls for validation (one of VeRO's anti-patterns).
7. Measure with paired runs on held-out cases (never the example pool): zero-shot, fixed examples and retrieved examples, per model and again after each model change; report accuracy, output-format errors, input tokens, cache hit rate and latency (retrieval with LLM reranking took about 6 s per question in one test), and for agents success, steps and tokens per episode (examples raised AppWorld input tokens per episode from 118,430 to 216,563 while steps fell from 19 to 12).

## How to measure

- **experiment** (Tier 3): paired runs on held-out cases, never the example pool: zero-shot with an explicit output format and a robust extractor, against fixed examples and against examples retrieved per query (1 to 5), per model and again after each model change, plus a bigger model zero-shot where that is the alternative; for agents, examples retrieved at each step against none; report accuracy (for data agents, sliced by questions on custom metrics or business logic and by questions that need several past queries), output-format errors, input tokens, cache hit rate, steps and latency, over several runs
- **monitor**: per request: which examples were retrieved and their similarity, whether the answer followed a retrieved pattern, output-format errors, input tokens and cache hit rate; weekly: failed questions or agent steps with no relevant example (gaps in the pool), questions that needed several past queries, and examples that no longer run after schema or metric changes

## Expected impact

- **Quality:** mixed, medium: data agents asked about custom metrics or underspecified business logic: 54% to 77% on 13 questions (Databricks, Feb 2026), 49% to 24% without the example-query index (Chen, Jul 2025), 54.27% to 60.95% with retrieved past queries and 61.31% at four examples (Zhou, Aug 2026), and on 2026 models 36.1% to 42.9% (GPT6-Luna) and 45.1% to 55.4% (Gemini4-Argon), with questions combining several past queries at 29.7% against 56.7% (Wang, Nov 2026); multi-step agents: retrieved trajectory windows raised GPT-4.1-mini from 0.28 to 0.55 on AppWorld and 0.18 to 0.87 on ALFWorld (Sarukkai, Dec 2025); a 2026 thinking model: 16 examples of the class it missed raised GPT-5.4 Thinking from 0.71 to 0.96 F1 (Adewumi, Apr 2026); strong models on math: 95.75% with eight examples against 95.83% zero-shot once the extractor was fixed (Cheng, Jun 2025), MATH train 0.81 to 0.83 with validation flat (VeRO, Feb 2026); o1-preview -2.2 to +1.2 points across six medical benchmarks (Nori, Nov 2024)
- **Cost:** mixed, medium: more input tokens per call: retrieved past queries raised input tokens per text-to-SQL request from 52.5k to 65.4k and 69.0k for GPT6-Luna, while storing verified queries as reusable parts and consulting the schema only on gaps cut them to 12.6k (Wang, Nov 2026); retrieved examples raised GPT-4.1-mini's input tokens per AppWorld episode from 118,430 to 216,563 (cost 0.09 to 0.15 of the teacher's), against 0.56 for zero-shot GPT-4.1, which scored lower (0.51 against 0.55) (Sarukkai, Dec 2025); examples retrieved per query change the prompt and defeat prefix caching, while caching a large fixed set and adding 20 retrieved examples cut estimated attention cost about 2x at 50 examples and 10x at 200 (Golchin, Jul 2025); few-shot o1-preview used more tokens than a tailored prompt for lower accuracy (Nori, Nov 2024); indexing a query log took about 5.2 s of LLM time per query (Zhou, Aug 2026)
- **Performance:** mixed, medium: retrieving and reranking examples per question with an LLM added about 6 s per question with serial API calls (Zhou, Aug 2026); retrieved examples raised end-to-end text-to-SQL latency for most models (Gemini4-Argon 181.6 s to 274.9 s per request), while answering from stored verified queries and skipping schema linking cut it 68.8% on average (Wang, Nov 2026); on a self-hosted engine prefill was 85.4% of latency, and without keeping retrieved examples in a cache-friendly order p95 latency was 46.97% higher (Wang, Jul 2025); in agents, examples cut steps per AppWorld episode from 19 to 12 (Sarukkai, Dec 2025)

## Caveats

The large gains come from data agents and tool-using agents on small or purpose-built sets: 13 questions in one Genie space, 133 LLM-judged questions in one run at LinkedIn, two benchmarks built so that past queries are needed (one generated and screened by LLMs), and AppWorld and ALFWorld with examples from runs on the same benchmarks' training tasks and a non-reasoning GPT-4.1-mini student; the only few-shot test of a named 2026 thinking model (GPT-5.4 Thinking, 0.71 to 0.96 F1) comes from a synthetic test run through the chat app, three runs, with examples of one class. On strong instruction-tuned and reasoning models solving math, examples mostly align the format and can hurt (eight examples tied zero-shot for Qwen2.5-72B, few-shot prompts collapsed on LSAT and CommonsenseQA in the same study's appendix, five examples lowered o1-preview on four of six medical benchmarks), and no source tests a 2026 thinking model on math or reasoning benchmarks. Retrieved examples are not reliably better than fixed ones and have limits: they did not beat zero-shot on a tool-selection benchmark, low-precision retrieval misled the model, questions combining several past queries scored 29.7% against 56.7%, and most agent failures were gaps no example covered; examples also add input tokens, and caching savings are measured only on one self-hosted log-parsing server, where swapping in cached examples lowered grouping accuracy on one of 16 datasets. Security, governance and brand effects are unmeasured, and VeRO lists adding examples where the problem calls for validation as an anti-pattern.
