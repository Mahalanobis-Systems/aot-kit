## What it is

Long system prompts cost more and can lose tasks: keep only what the model needs, state each rule once in a named section, and say which source wins a conflict. It pays most where always-loaded text or rules have piled up: in an agent harness on a current thinking model, a median 2,549-word expert profile as the system prompt left accuracy on nine science benchmarks unchanged (-0.6 points), cost 2.2 to 4.5 times more per answer and solved 46.7% of tool-using tasks against 56.7% with a one-line prompt, largely because more runs hit their token and time limits; with 80 rules in one prompt at most 1.9% of responses met them all across five current models; and one sentence giving existing code precedence over a stale instruction file raised the share of two frontier coding agents' choices that followed the code from 4.2% to 91.4%. Restructuring alone is not a reliable gain: a one-call merge-and-rank rewrite recovered 11.0 points of follow rate for GPT-5-mini but -1.2 for Claude Sonnet 4.6, markdown against plain text made no reliable difference, and in VeRO's TerminalBench runs a three-section rewrite broke as many passing tasks as it fixed while the hardest cut gave the best pass rate (37.1%). Cut with care and judge on held-out cases: deleting a safety rule that another rule backed up showed no harm under the agent's model but led to credential misuse after a switch to a weaker model, and on one deep-research agent an optimizer-written prompt gained 0.079 held out against 0.202 on its validation set.

## When it applies

- **In the code:** system prompt with no named sections; requirements repeated, contradictory, or absent (no answer format, no completion criteria); pairs of rules that cannot both hold (JSON output and markdown headers); several dozen or more simultaneous rules in one prompt; context files that restate what the agent can find in the repository (overviews, directory listings); case-specific facts or answers left in the prompt by an optimizer; prompt plus tool descriptions over about a quarter of the context window; broad always-loaded guidance (role profiles, handbooks, generic checklists) of thousands of tokens resent every turn; instruction files that name paths, commands or conventions the code no longer uses, with no rule for which source wins; rules that may conflict placed only in tool or skill descriptions; safety rules that back each other up, so deleting one would show no harm
- **In traces:** failure rows labeled instruction-following-failure or instruction-grader-mismatch where the requirement was never in the prompt; prompt tokens the largest share of input per step; context-overflow outcomes; runs stopped at a token or time limit, more often with the longer prompt; final replies that name a conflict between the instructions and the code and follow the instructions anyway
- **In eval results:** an ablation that removes a section and shows no loss (cut it, unless it is a safety rule: then check that what remains still blocks the harm with each other safeguard removed, under the weakest model you may route to), especially one that also lowers cost; failures that cluster on one step of the task procedure (add it); compliance per rule that falls as rules are added or is no higher than with the rule withheld, or pairs of rules that fail together more often than each fails alone; an optimized prompt whose validation gain far exceeds its held-out gain, or that changed text outside the sections it was meant to edit
- **Probes:** One deterministic check per rule in the prompt, context files and tool and skill descriptions, run with all rules, with each rule alone, with each rule withheld and with each section removed.

## How (outline)

1. Start from the current prompt as the baseline: run it on development and held-out cases and record pass rate, which cases pass and fail, compliance with each rule, steps, input tokens, cost per task and runs that stop at a turn, token or time limit. List every instruction the model receives (system prompt, context files such as AGENTS.md, tool and skill descriptions, checklists) and the requirements the task actually has, from the task spec and from failures.
2. Cut what the model does not need: content it can find or would do anyway (repository overviews, restated documentation, broad role profiles), duplicated rules, statements about the code or environment that are no longer true, and leftovers such as answers to specific eval cases. Always-loaded text is paid on every turn: in an agent harness on Gemini 3.8 Flash at low thinking, a profession profile as the system prompt (median 2,549 words) added 4,281 to 5,573 input tokens per call, raised cost per successful answer 2.2 to 4.5 times and moved accuracy on nine science benchmarks by -0.6 points [-1.5, +0.2], and on 60 tool-using bioinformatics tasks it solved 46.7% against 56.7% with a one-line prompt, largely because more runs hit the 600,000-token or 35-minute limit (88 against 61 of 180); a one-sentence role stayed near baseline cost. Across four coding agents, LLM-generated context files changed success by -0.5% and -2% while adding 20% and 23% to cost, their overviews did not shorten the search for the relevant file, and dropping only the testing section cut cost per task from $0.4715 to $0.3730 with no significant change in accuracy; the same files helped (+2.7%) only once the repository's other documentation was removed. Correct or remove stale lines rather than leaving them: agents followed a stale instruction file in 90.1% of choices, and Claude Code named the conflict in 79 of 80 runs and still followed the file. Keep what the model cannot infer, such as non-standard conventions and requirements (developer-written files did better than generated ones). In VeRO's TerminalBench run, cutting the prompt from 7 lines to 3 and its checklist from 10 lines to 4, with shorter tool descriptions (2.a.ii) and a tighter output cap in the same commit, gave the best pass rate, 37.1%, and context-overflow failures fell from 13 to
2. 3. Do not cut a safety rule because removing it changes nothing. Where rules back each other up, deleting one adds almost no observed harm while another still blocks it (0.016 against 0.422 when nothing else did), so gates that judged cuts on task success removed them unseen: a greedy gate left 5 of 6 harnesses unprotected, and harnesses that still looked safe under the agent's model misused credentials in 0.30 of runs under a weaker model, against 0.004 for harnesses cut under a paired significance test. Mark safety text as frozen, accept a cut only if every remaining one-rule ablation still blocks the harm (no AppWorld loop ended unprotected that way, with no loss of clean success), and rerun the safety probes under every model you may route to.
4. State each remaining requirement once, in a named section, and give the answer format and the completion check their own sections (what the format says and how the answer is read is 9.b.i). Merge duplicates and settle conflicts: where two rules cannot both hold (JSON output with markdown headers), drop one or say which wins, and where the instructions may disagree with what the agent finds, say in one sentence which source wins. In 40 Python projects whose instruction file contradicted the code, adding 'When a repository's documentation and its existing code disagree, follow the conventions used in the existing code, and in your final reply point out each inconsistency you found between the documentation and the code' to the user-level instruction file raised the share of choices that followed the code from 4.2% to 91.4% and the test pass rate from 89.4% to 100% for Claude Sonnet 5.5 in Claude Code and GPT-6 Sol in Codex CLI, and stopped Codex CLI rewriting working code (20 of 80 runs without it). Keep the count down, since compliance falls as rules stack: three models followed about 96% of instructions given one at a time but 20% to 60% with twenty; in another study the share of responses meeting every rule fell from 0.59-0.94 with 10 rules to at most 0.019 with 80, and that author recommends treating about 40 rules as the point to split them across turns, tools or a validation check (not tested); and 12 frontier coding agents followed 72.1% to 85.9% of the applicable rules when 25 to 35 were placed in each multi-turn task, 3.6 to 7.4 points fewer of those that go against what the model does unprompted, with output-control rules lowest (70.9%). A one-call rewrite that grouped rules by kind, merged duplicates, added a precedence note for conflicts and listed reasoning rules first and format rules last recovered 11.0 points of follow rate for GPT-5-mini and 3.3 for Gemini 2.5 Flash but -1.2 for Claude Sonnet 4.6, so expect the most from smaller models.
5. Pick one consistent way to mark sections (headings or tags) and do not expect the format itself to buy accuracy: across five current models none showed a reliable markdown advantage over plain text for a block of rules, and the one consistent difference favored plain text (4.8 points for one Qwen model at 160 rules). Test format and placement on your own model: Gemini Flash fell 18.1 points with 40 rules written as prose, moving the same rules from the system prompt to the user turn changed adherence by -8.7 to +6.6 points depending on the model, and in a conflict test on nine models, rules in the system prompt, a project file or the user turn tied for precedence ahead of tool descriptions and then skill descriptions, so keep rules that may conflict out of tool and skill descriptions.
6. Add a domain procedure section only if failures cluster on a step; write it from those failures or from an expert, or generate variants with an optimizer such as GEPA. If an optimizer writes it, judge it on held-out cases that share no topic with those it saw, over several seeds, strip case-specific content, and diff what it changed outside the sections it was meant to edit: on a deep-research agent GEPA's held-out gain was 0.079 against 0.202 on its 24-task validation set, memorized answers made up 52% and 39% of the two winning prompts without adding reward, the two longer candidates regressed, and a hand-written prompt keeping only the rules it found recovered about 57% of the gain; in AppWorld, GEPA's validation gains of up to +0.22 did not hold on fresh tasks (0.35 to 0.45 against 0.40 for the original), and two of its three final prompts kept every credential rule verbatim but rewrote a note template into an instruction to log in with stored credentials, which a weaker model then misused in 2 and 5 of 40 runs (0 of 80 for the original).
7. Run the paired eval, old against restructured prompt, on the full development and held-out sets, not a subset (a VeRO rewrite scored 45% on a 20-task subset, then broke as many passing tasks as it fixed); report new passes and regressions per case as well as the net, compliance per rule (also with the rule withheld, so rules the model follows anyway do not inflate it), context-overflow failures and runs stopped at a budget limit, steps, tokens and cost; keep only sections that earn their place, keep safety text frozen, and rerun after any model change, including a switch to a cheaper model.

## How to measure

- **experiment** (Tier 3): paired eval, old against restructured prompt, on the full development and held-out sets (topics disjoint from any an optimizer saw), over several runs or seeds and for each model in use, including any cheaper model you may route to: pass rate with new passes and regressions per case, compliance per rule from one deterministic check per rule (with the rule present and withheld), context-overflow failures and runs stopped at a turn, token or time limit, steps, input tokens and cost per task; remove one section at a time to find sections that cost tokens without changing outcomes, but remove a safety rule only if what remains still blocks the harm with each other safeguard also removed
- **monitor**: in production: violation rate per rule and format-compliance rate on sampled traffic, prompt tokens as a share of input per step, steps, budget-limit stops and cost per task, prompt growth (rules and lines added since the last restructure), and lines in the prompt or context files that no longer match the code or environment (paths, commands, conventions); rerun the paired eval and the safety probes when the model changes, since the value of a rewrite depended on the model and lost safeguards showed up only under a weaker model

## Expected impact

- **Quality:** mixed, medium: cutting: a long always-loaded expert profile moved accuracy on nine science benchmarks by -0.6 points [-1.5, +0.2] and lowered a tool-using solve rate from 56.7% to 46.7% under fixed token and time limits (Kassis, Sep 2026); repository context files changed coding-agent success by -2% to +2.4%, none significant (Gloaguen, Feb 2026); TerminalBench +6.8 points where the prompt crowded out context, GPQA train -0.04 where the optimizer could change only prompts, tool descriptions and parameters (VeRO, Feb 2026); settling conflicts: one precedence sentence raised choices that followed the code from 4.2% to 91.4% and test pass rate from 89.4% to 100% (Xu, Oct 2026); restructuring: a one-call rewrite of stacked instructions +11.0 points of follow rate for GPT-5-mini, +3.3 for Gemini 2.5 Flash, -1.2 (not significant) for Claude Sonnet 4.6 (Anand, Jul 2026); a dedicated verification section +4.75 to +5.0 points on GSM-Plus (Cemri, Mar 2025); a three-section rewrite gave 6 new passes and 6 regressions on TerminalBench, and MATH validation +0.10 with train -0.07 (VeRO, Feb 2026); an optimizer-written procedure on a deep-research agent +0.079 held-out reward (Lumer, Oct 2026); rule load: 12 frontier coding agents followed 72.1% to 85.9% of applicable rules with 25 to 35 per task (Huang, Aug 2026); format: no reliable markdown advantage over plain text across five models (Eliav, Jul 2026)
- **Cost:** mixed, medium: cutting saves: an expert profile as the system prompt added 4,281 to 5,573 input tokens per call, 1.5 to 2.3 times the output tokens and 2.2 to 4.5 times the cost per successful answer with no accuracy gain, while a one-sentence role stayed near baseline (Kassis, Sep 2026); LLM-generated context files raised cost 20% and 23% and developer-written ones up to 19% with no significant gain in success, and dropping one testing section cut cost per task from $0.4715 to $0.3730 (Gloaguen, Feb 2026); adding can cost more: followed instructions brought extra testing and exploration (2.45 to 3.92 more steps per task) (Gloaguen, Feb 2026), and an optimized deep-research prompt raised policy tokens per query about 32%, 146.0k to 193.1k, on 6 queries (Lumer, Oct 2026); context rendered as markdown costs 1.258x the tokens of plain text (Eliav, Jul 2026)
- **Performance:** improves, small: cutting saves steps and budget: context files added 2.45 to 3.92 steps per task and raised GPT-5.2's reasoning tokens 22% on SWE-bench (Gloaguen, Feb 2026); with a long expert profile resent every turn, 88 of 180 tool-using runs stopped at the token or time limit against 61 of 180 with a one-line prompt (Kassis, Sep 2026); a precedence sentence slightly cut tool calls and running time (Xu, Oct 2026); an optimizer-written prompt added no latency (138.8 s against 159.9 s per query, 6 queries) (Lumer, Oct 2026); one exception: on one provider the one-line prompt failed on the first API call in 27.9% of calls against 1.2% for the long one, cause unknown (Kassis, Sep 2026)

## Caveats

Restructuring is not a reliable gain on its own: in VeRO's TerminalBench study a rewrite into three named sections scored 45% on a 20-task subset but broke as many passing tasks as it fixed on the full set (6 new passes, 6 regressions), the run that cut the prompt hardest also shortened tool descriptions, set the output cap to 17 KB and left 11 parser crashes in place, and on reasoning tasks (GPQA, MATH) VeRO's optimizers, including its prompt-only variant, gained little or nothing. The value depends on the model: a merge-and-rank rewrite of stacked rules helped smaller models and was neutral to negative for the strongest (Claude Sonnet 4.6 went from 0.627 to 0.560 at twenty instructions, significant only at that size), format effects were small and changed sign between models, a hand-written version of the deep-research optimizer's rules recovered about 57% of its gain with a confidence interval that included zero, and safety rules lost to cutting caused harm mainly under weaker models (a gap of 0.025 under two strong models). The newer studies are narrow: the agent cutting result is one model (Gemini 3.8 Flash at low thinking), one harness and 60 tool-using tasks run three times, from the company that publishes the profiles, and there the one-line prompt failed far more often on the first API call (27.9% of calls against 1.2%); the precedence sentence covers 40 synthetic Python projects, two agents and two runs per cell; 86.8% of the frontier rule-following verdicts come from an LLM judge (62.1% agreement with a second judge) and its precedence order from a pilot on nine older models; and the safeguard study covers two environments with four written rules each. Earlier format and context-file studies are also narrow (synthetic verifier-checked rules with 20 trials per cell; Python repositories with one sample per setting), no study yet restructures, rather than shortens or adds to, a frontier thinking agent's own system prompt at matched compute, and governance and brand effects are unmeasured, so measure the change on your own agent.
