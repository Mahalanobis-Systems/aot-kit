# start

Every optimization in AOT Kit has its own skill, named below. All are **placeholders** for now:
each describes the change, the signals that say it applies, and how to measure it, but does not
yet walk through applying it.

When the person asks which optimizations fit their agent:
1. Ask what they have: the agent's code, traces, and an eval (aot-evals, or their own).
   The tier an optimization sits in says what evidence it needs; don't recommend a Tier 3 or 4
   change to an agent with no quality eval or production baseline.
2. Name the few skills whose signals match what you see, and load the one they pick.

`${CLAUDE_PLUGIN_ROOT}/catalog.yaml` has each skill's catalogue id, categories and the library
patterns it absorbs.

**Tier 1, Hygiene:** no-regret changes that cannot alter what the model sees; checked by exact replay or ~10 hand-labeled examples.

- `rewrite-tool-surface` (2.a.ii): Rewrite the tool surface: names, schemas, descriptions
- `reduce-tool-surface` (2.a.i): Reduce the tool surface: remove and consolidate tools, then defer the rest behind search
- `cache-stable-prefix` (3.b.i): Keep the prompt prefix cache-stable

**Tier 2, Reliability:** remove hard failures (crashes, loops, timeouts, injection); measured as failure rate before and after.

- `detect-loops-and-stalls` (7.b.i): Detect stalls and loops: warn, then stop early
- `fail-soft-tools` (2.b.i): Make tool calls and tool results fail soft, and retry transient failures
- `size-execution-budgets` (7.b.iii): Size run budgets so productive runs aren't cut off: turn caps, deadlines, command timeouts
- `staged-compaction` (5.a.i): Compact conversation history in stages: elide stale tool outputs, then keep an anchored summary
- `extractable-final-answer` (9.b.i): Make the final answer reliably extractable: state the format, extract robustly, force an answer at the limit
- `tune-search-tool` (8.b.i): Tune the search tool: snippets, enough results, retries, reformulation, filters, source quality
- `external-verifier-feedback` (9.a.i): Feed back a sound external verifier's verdict; never the model's own critique
- `verify-completion` (9.b.iii): Verify completion against the environment before the agent stops
- `false-success-detector` (9.b.ii): Triage false success with a cheap trained detector, not an LLM judge
- `constrain-agent-reach` (10.a.i): Constrain what the agent can touch
- `risky-action-policy` (10.b.i): Gate irreversible actions: allow, ask or deny by side effect
- `contain-untrusted-input` (10.c.i): Contain sensitive data and untrusted input
- `keep-errors-in-context` (7.b.ii): Keep errors in context
- `filesystem-checkpoints` (4.b.i): Filesystem-based agent state and checkpoints

**Tier 3, Tuning:** real trade-offs within the existing design; needs the calibrated quality eval and a paired comparison.

- `bound-tool-output` (2.c.i): Bound tool output: cap it, or write it to a file the agent can read
- `restructure-system-prompt` (3.a.iv): Restructure the system prompt: every requirement once, up front, in named sections; nothing the model doesn't need
- `tool-use-guidance` (2.b.ii): Tell the agent when to use each tool, in context it always sees
- `few-shot-examples` (3.a.i): Add worked examples to the prompt (few-shot), or curated example queries for data agents
- `surface-unreadable-information` (8.a.ii): Surface information the source holds but the agent cannot read
- `ground-queries-in-schema` (5.b.i): Give the model the schema it queries, in context: descriptions, keys, codes, sample values
